# depgraph v0.2.0-rc.1

This prerelease is the Milestone 2 Semantic Graph release candidate. It combines the safe static package/file graph with versioned semantic definition, import, type, value-reference, call, and framework relationships for Rust, Go, and TypeScript/JavaScript repositories.

## Compatibility unit

| Component | Version |
| --- | --- |
| Product and Rust/Go/Web adapters | `0.2.0-rc.1` |
| NDJSON protocol and graph schema | `1.0` |
| Rust/Cargo baseline | `1.93.1` |
| Go baseline | `1.26.1` |
| Node.js / pnpm baseline | `24.18.0` / `10.33.0` |
| Bundled TypeScript compiler | `7.0.2` |
| rust-analyzer / Salsa backend | `0.0.330` / `0.26.1` |

The release tag is `v0.2.0-rc.1`. Cargo product crates, Rust/Go/Web worker handshakes, release manifests, SBOM roots, and archive names all carry `0.2.0-rc.1`. Protocol and schema compatibility remain `1.0`.

## Semantic graph scope

### Rust

- Canonical symbol, type, and generic-instance definitions from the pinned rust-analyzer library backend.
- Import, re-export, type-use, exact direct call, and conservative closed candidate call relations.
- Confined Cargo metadata and inventory-only project loading; build scripts and proc macros are not executed.
- A profile is `semantic-complete` only when the compatible backend, confined project model, syntax ledger, semantic ledger, and zero-gap coverage gates all succeed.

### Go

- Canonical package, symbol, type, generic-instance, value-reference, type-use, and call graph relations from `go/packages`, `go/types`, and serial SSA.
- Exact static calls plus RTA/CHA candidates, with explicit opt-in VTA refinement.
- Reflection, unsafe, `go:linkname`, assembly, plugin, cgo, and native callback boundaries remain explicit reasoned sites instead of fabricated exact targets.
- Offline dependency snapshot identity covers admitted module requirements, replacements, checksums, vendor metadata, and referenced dependency source bytes.

### TypeScript/JavaScript and frameworks

- Bundled-only TypeScript `7.0.2` definition, import, re-export, type-use, exact-call, and closed local candidate-call graph.
- Next.js route/component/render/client/server boundaries.
- Astro component/render/hydration, content, and asset relations.
- TanStack Router typed route relations and TanStack Start server-function/RPC/middleware relations.
- Framework profiles require every detected versioned semantic slice and the common TypeScript graph to pass before claiming `semantic-complete`.

## Safety and completeness boundary

The default scan does not execute project configuration, plugins, package managers, generators, build scripts, proc macros, or project-local TypeScript. Repository toolchain aliases, relative `PATH` entries, Node execution hooks, out-of-root symlinks, undeclared runtime-tree entries, and manifest/checksum mismatches fail closed.

Every recognized dependency occurrence is retained as `resolved`, `candidates`, `external`, or `unresolved`. Candidate and external sites are compatible with semantic completeness; skipped input, unsupported syntax, unresolved sites, compiler diagnostics, semantic validation errors, or detected framework slice failures prevent the completeness claim.

## Known limitations

- Build observation and `phase=build` evidence are not included in this release candidate.
- Dynamic or build-only framework routes and boundaries remain reasoned unresolved sites.
- Rust sysroot / `rust-src` is not bundled, and packaged scans never fall back to project or system backend bytes.
- Go reflection and native boundaries are conservatively incomplete even when nearby ordinary calls resolve exactly.
- Incremental/watch mode, snapshots/diff/impact, architecture policy, runtime trace import, and GraphML export remain future milestones.
- This is a prerelease compatibility candidate, not a stable `0.2.0` declaration.

## Published artifacts

The release workflow publishes archives and SHA-256 sidecars for:

- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`
- `x86_64-apple-darwin`
- `aarch64-apple-darwin`
- `x86_64-pc-windows-msvc`

Each target runs the native package gate before upload. A separate publish gate then re-downloads the complete five-target set, verifies every checksum, archive layout, release manifest, core/schema/worker/runtime digest, worker compatibility attestation, SPDX SBOM root, and the separation of complete project license texts from the third-party license inventory. Its `release-verification.json` report is attached to the GitHub Release.

## Verification

The tag workflow must complete these jobs before publication:

- `quality`: formatting, lint, Rust/Go/Web unit and integration tests, race tests, and semantic CLI E2E.
- `benchmark`: the Milestone 2 benchmark gate.
- `package`: native package/query/export/safety verification on all five targets.
- `verify-assets`: aggregate checksum, manifest, SBOM, license, and attestation verification.
- `publish`: GitHub prerelease creation from the verified tag.

Representative packaged usage:

```sh
depgraph doctor --json
depgraph scan /path/to/repository --json
depgraph deps 'symbol:<resolver>' --json
depgraph dependents 'type:<resolver>' --json
depgraph why 'symbol:<source>' 'symbol:<target>' --json
depgraph export --format json --output graph.json
depgraph export --format dot --output graph.dot
depgraph export --format mermaid --output graph.mmd
```
