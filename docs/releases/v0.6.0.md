# depgraph v0.6.0

`v0.6.0`は、コードの健全性を調べるCLI／MCP APIと、大規模解析の分割・再開機能を追加する。
Storeはschema 19、操作ジャーナルはschema 6、操作DTOはv2へ更新する。
アップグレード前にStoreと操作ジャーナルをバックアップする。
このファイルの追加だけでは公開完了にならない。署名付きtag、GitHub Release、公開後証跡が同じsourceを指して初めてstableと認める。
詳細な判断は[ADR-011](../40_arch_design/adr-v0.6-release-contract.md)に記載する。

## 公開済みv0.5.4との境界

公開済み`v0.5.4`は、Store schema `17`を実装するimmutableな履歴である。
annotated tag objectは`0affa3af15a4854f78a2c6d4b1308e4647c39f88`、peeled source commitは`ea16edec63e88923c7d169152caedbf4285b4713`である。
tag、source、Release asset、`release-post-publish-evidence-v0.5.4.json`は移動・置換・再利用しない。

`v0.6.0`はcurrent `main`のStore schema `19`をstableへ昇格する。
schema 19へ移行したStoreを公開済み`v0.5.4` binaryで開くことは禁止する。

## Code-health API

`v0.6.0`は、説明可能なcode-health findingをCLIとMCPの共通契約として公開する。
CLIは`health`、`health list`、`health show`、`cleanup`、`audit`、`hotspots`を提供する。
MCPは`health_summary_get`、`health_findings_list`、`health_finding_get`、`health_audit_get`、`health_hotspots_list`を提供する。

現在のhotspot出力は、fan-in、fan-out、reverse impact、Git churn、runtimeの5層を`hotspot_scores`へ構造化する。
hotspotのconfidenceは`probable`を上限とし、`confirmed`は未使用を証明するfindingに限定する。
sourceの自動変更や、欠落した証拠の推測による補完は行わない。

開発線のAPI変更もv0.6.0の移行対象である。
`score_hotspots`は`Vec<HealthFinding>`ではなく`Result`を返し、`HotspotAnalysisError::InvalidInput`、cancel、resource errorを返す。
現在のhotspot `HealthFinding`を直接生成するcallerは`hotspot_scores`を設定し、Agent DTO projectionもhotspot findingへclosed score objectを出力する。
non-hotspot findingはこのfieldを出力しない。legacy hotspotのwire inputに限りmissingまたはnullを受理し、現在のv0.6.0 hotspot出力では許可しない。

## 大規模解析の分割と再開

Go／Webの解析を処理単位に分割し、中断後は有効な解析結果を再利用する。
Goはパッケージ単位で読み込み、大きな単一パッケージの関数本体も段階的に処理する。
healthはStoreの範囲ごとに読み込み・集計し、完了した範囲の結果を再利用する。
予算を超えた解析はpartialとして明示し、未完了をcompletedとして扱わない。

元の試験対象では、macOS arm64でfresh scan、通常のhealth、同一入力の中断・再開が完了した。
検証commitは`5a1587dd372f22854ae2a75deb0cf9b787f133ed`で、個別の資源上限は製品の既定値を維持した。
完了記録は[#482](https://github.com/TamaT-LLC/depgraph-cli/issues/482)と[#464](https://github.com/TamaT-LLC/depgraph-cli/issues/464)にある。
対象の名前やソースなどの非公開情報は掲載しない。

## Store migration

schema 17から19への移行はトランザクション内で行う。
schema 18はpolicy digest、health analyzer version、finding contract versionの列を追加し、新規scanではこれらをcompleted snapshotのseal v2へ結合する。
schema 19は解析attemptと処理単位の永続台帳を追加する。
既存schema-17 scanはlegacy seal v1を検証してから移行し、provenanceが無いままでもよい。provenanceが欠ける、または一致しない比較は`incomparable-policy`または`incomparable-contract`としてfail closedにする。

移行前に書き込み処理を停止し、Storeと操作ジャーナルのそれぞれでdatabaseとWAL/SHMを一組としてバックアップする。
rollbackではschema 19のStoreを診断用に退避し、Storeと操作ジャーナル両方のdatabase/WAL/SHM一式を復元してからv0.5.4 binaryを起動する。
旧binaryによるdowngrade-in-placeや、SQLite tableの個別コピーは行わない。

移行元は公式`v0.4.0-rc.6`のStore schema `13` fixtureである。
fixtureは`xtask/fixtures/v0.4.0-rc.6-store-v13.sql`に固定し、SHA-256は`43fe0dda73d03be9b8fff2ed9ff8ce888ad96e41e78335a1117646475c937150`とする。

## Release source and verification

1. version change、release note、ADRを一つのPRにまとめ、CI成功とGreptileの未解決指摘ゼロを確認してマージする。
2. `main`を一時freezeし、そのcommitで`extra_native_packages=true`を指定したmanual Full CIの11ジョブすべてを成功させる。
3. `refs/heads/release/0.6`を同じcandidate SHAに作成する。既存refならfast-forwardで更新する。
4. `v0.6.0`のsigned annotated tagを同じsource SHAへ作成する。
5. Release workflowで5 targetのarchive、compiler pack、checksum、manifest、SBOM、license、MCP smokeを検証する。
6. 公開後にasset closure、stable gate、code-health CLI/MCP parity、Agent host canaryを検証し、`release-post-publish-evidence-v0.6.0.json`を同じReleaseへ追加する。
7. GitHub Releaseと証跡が成立した後に、npm workflowを`v0.6.0`へdispatchする。

`v0.5.4`のtag object、peeled source、asset、evidenceをv0.6.0のcandidateとして再利用しない。

v0.6.0は`@tamat-llc/depgraph`と`@tamat-llc/depgraph-win32-x64`を含む5 targetのnative packageを公開する。
npm publicationには`npm Trusted Publishing`を使い、Node.js 24以上を要求する。
musl targetは対象外であり、`v0.6.0`のnative jobは`mcp-package-smoke-v3`を使う。
stable gateは製品価値の`agent-dogfood-report-v1`に加え、Issue #436のcode-health `agent-dogfood-report-v2`を14 gateで検証する。
code-health reportは`fixtures/agent-dogfood-v2/evidence/v0.5.4-rc.2/report.json`に固定する。
code-health reportの固定SHA-256は`7cb90ae38161e375ac080f475de6c8ab36dc18afc3ce243f6cdf7306d759547f`である。

## Support status

公式`v0.6.0` Releaseとmatching post-publish evidenceが揃うまでは、公開済み`v0.5.4`がsupported stable lineである。
current `main`と`v0.6.0-rc.N`は評価用artifactであり、v0.5.4のbinary、worker、compiler pack、Storeと混在させない。
