# depgraph v0.6.3

`v0.6.3` は v0.6.2 に対する stable patch release であり、Web スキャンの参照解決と診断を改善する。
公開の完了には、署名付き tag、GitHub Release、同一 source の公開後証跡を必要とする。

## Web の参照解決

`./data.gen` や `./auth.callback` のように、拡張子を省略した名前にドットを含む import を解決する。
同形式のディレクトリにも対応し、実在するアセットへの参照は維持する（[#516](https://github.com/TamaT-LLC/depgraph-cli/issues/516)）。

TanStack Router のルート ID と URL を区別し、pathless route の生成ツリー照合を修正する。
末尾スラッシュのある登録と遷移先も同じ URL として検索する。
同じ URL を持つレイアウトとページは別ノードとして保持し、参照先が曖昧な場合は候補を残す（[#517](https://github.com/TamaT-LLC/depgraph-cli/issues/517)、[#518](https://github.com/TamaT-LLC/depgraph-cli/issues/518)）。

TypeScript の `typeof` と `typeof import(...)` を値の依存として扱い、const tuple・関数・クラスなどの参照先を保持する。
通常の型参照には従来の型ノード検証を適用する（[#521](https://github.com/TamaT-LLC/depgraph-cli/issues/521)）。

pnpm lockfile の importer と manifest が一致する場合、依存元ごとにバージョンと peer dependency の組み合わせを絞る。
証拠が不足する場合は候補を維持し、exports の条件評価と組み合わせる（[#522](https://github.com/TamaT-LLC/depgraph-cli/issues/522)）。

## インストール済みパッケージの型宣言

リポジトリ内にインストール済みの型宣言を隔離されたコンパイラーへ取り込み、戻り値・hook・ジェネリックなチェーンを通る呼び出しを外部パッケージまで追跡する（[#520](https://github.com/TamaT-LLC/depgraph-cli/issues/520)）。
外部の型宣言をローカルのソース定義として登録せず、解決先は外部パッケージの境界として記録する。

一つのコンパイラー環境で最大 1,024 宣言ファイル、合計 16 MiB、1 ファイル 1 MiB、8,192 モジュール要求まで読み込む。
リポジトリ外へのリンク、矛盾する解決先、欠けた参照、上限超過は診断に残し、意味解析が完全とは判定しない。
プロジェクトの JavaScript、TypeScript コンパイラープラグイン、パッケージマネージャー、ビルドスクリプトは実行しない。
依存パッケージの追加インストールも行わない。
型宣言と package metadata の変更をキャッシュ・解析単位の再利用判定に含める。

## 診断の区別

対象外のファイル形式は `unsupported_file_kind` としてスキップし、構文未対応の件数に含めない（[#519](https://github.com/TamaT-LLC/depgraph-cli/issues/519)）。
スキップは引き続き strict policy と解析の完全性に反映する。
隔離環境での型診断には解析環境と省略件数を表示する。

実在する CSS・画像の import は構文解析でファイル依存として保持する。
意味解析では、型宣言の不足をファイル不存在と区別する（[#523](https://github.com/TamaT-LLC/depgraph-cli/issues/523)）。

CLI の既定値、Store スキーマ、公開プロトコルのノード・エッジ種別、依存パッケージは変更しない。
内蔵 TypeScript は 7.0.2 を維持する。
解析プロファイルのモジュール解決方式は `inventory-and-confined-declarations` となる。
以前の `inventory-only` プロファイルも引き続き検証できる。

## Release source and verification

1. version change、release note、ADRを一つのPRにまとめ、CI成功とGreptileの未解決指摘ゼロを確認してマージする。
2. `main`を一時freezeし、そのcommitで`extra_native_packages=true`を指定したmanual Full CIの10ジョブすべてを成功させる。Intel macOS（`macos-15-intel`）は対象外である。
3. `refs/heads/release/0.6`を同じcandidate SHAに作成する。既存refならfast-forwardで更新する。
4. `v0.6.3`のsigned annotated tagを同じsource SHAへ作成する。
5. Release workflowで4 targetのarchive、compiler pack、checksum、manifest、SBOM、license、MCP smokeを検証する。`x86_64-apple-darwin` は構築しない。
6. 公開後にasset closure、stable gate、code-health CLI/MCP parity、Agent host canaryを検証し、`release-post-publish-evidence-v0.6.3.json`を同じReleaseへ追加する。
7. GitHub Releaseと証跡が成立した後に、npm workflowを`v0.6.3`へdispatchする。

`v0.5.4`のtag object、peeled source、asset、evidenceをv0.6.3のcandidateとして再利用しない。

v0.6.3は`@tamat-llc/depgraph`と`@tamat-llc/depgraph-win32-x64`を含む4 targetのnative packageを公開する。`@tamat-llc/depgraph-darwin-x64` は公開しない。
npm publicationには`npm Trusted Publishing`を使い、Node.js 24以上を要求する。
musl targetは対象外であり、`v0.6.3`のnative jobは`mcp-package-smoke-v3`を使う。
stable gateは製品価値の`agent-dogfood-report-v1`に加え、Issue #436のcode-health `agent-dogfood-report-v2`を14 gateで検証する。
code-health reportは`fixtures/agent-dogfood-v2/evidence/v0.5.4-rc.2/report.json`に固定する。
code-health reportの固定SHA-256は`7cb90ae38161e375ac080f475de6c8ab36dc18afc3ce243f6cdf7306d759547f`である。
