# depgraph v0.4.0-rc.1

This prerelease is the Milestone 4 Incremental and CI release candidate. It
adds immutable snapshots and graph diffs, changed-set impact, persistent
syntax/semantic/build caches, watcher-driven invalidation, architecture policy
and GitHub annotations, collector-independent runtime evidence, deterministic
GraphML, and a reproducible 10,000-file benchmark to the Milestone 2 semantic
graph and Milestone 3 build-evidence foundation.

## Migration and upgrade

Opening an older writable store performs an in-place, transactional migration
to schema `11`. The release package gate creates a schema `5` store using SQL
captured from the official `v0.2.0-rc.1` archive, opens it with the packaged
`v0.4.0-rc.1` CLI, and verifies all of the following:

- The last completed scan becomes an immutable completed snapshot.
- Its snapshot ID passes the integrity verifier.
- The retained node, dependency site, edge, evidence, coverage, and profile are
  still queryable.
- Naming the migrated snapshot does not change its immutable ID.
- `why` still traverses the dependency represented by the old store.
- The untouched rollback copy remains schema `5`.

Before upgrading a persistent store, stop its daemon and make a byte-for-byte
copy of the database and its `-wal` / `-shm` files after SQLite has been cleanly
closed. Downgrade-in-place is not supported: a `v0.2.0-rc.1` binary cannot read
schema `11`. To roll back, stop the new daemon, remove the upgraded working copy,
restore the complete pre-upgrade schema `5` backup, and use the old binary. Do
not copy individual tables between schema versions.

Stores newer than schema `11` fail closed. Read-only commands require an exact
supported schema and never silently rewrite a store.

## Milestone 4 packaged smoke

Every native archive runs the same package gate before upload:

- `snapshot create/list/show` retains two named immutable completed snapshots.
- `diff` reports the added source graph and preserves canonical snapshot IDs.
- `impact` resolves and traverses the changed file.
- The daemon observes a filesystem change, records an
  `incremental-plan-v1`, completes the replacement scan, and stops cleanly.
- Architecture policy JSON and `--github-annotations` return a clean CI result
  for the packaged fixture.
- The packaged `runtime-collector-v1` observes the real application fixture,
  emits a redacted trace, and feeds `validate` / `import`; the completed runtime
  snapshot remains queryable through runtime phase/session filters.
- GraphML `1.0` is byte-identical across repeated stdout exports; atomic file
  output matches stdout and leaves no temporary output behind.
- The old schema `5` migration described above retains its completed graph.

The existing package closure also verifies safe Rust/Go/Web scans, semantic
completeness, framework graphs, build-observation consent, crash/timeout
rollback, worker/runtime tamper failure, deterministic checkout-independent
exports, project licenses, third-party notices, and the SPDX SBOM. The runtime
collector is checksum-attested in the manifest, represented as a first-party
SBOM package, declared dependency-free in the build/license inventory, and
fails closed when missing, modified, or version-mismatched.

The Next.js package gate consumes stable 16.2+ Adapter API route/output
manifests through `next-build-observation-v2`. RSC/data variants share their
canonical route, prerenders preserve exact parents, metadata routes and
server/client/edge/static boundaries remain observed, and build-ID-scoped paths
are checkout-independent. Missing or partial manifests fail closed before
promotion.

The dynamic framework release gate is
`dynamic-framework-evidence-release-gate-v1`. Its manifest ledger pins:

- Next.js `next-adapter-api-16.2-v1` / `next-build-observation-v2` / observer `0.2.0`.
- Astro `astro-integration-v5-v7-vite-v6-v7-v1` /
  `astro-build-observation-v2` / observer `0.2.0`.
- TanStack Router `tanstack-router-v1-vite-v6-v7-generated-route-v1` /
  `tanstack-router-build-observation-v1` / observer `0.1.0`.
- TanStack Start `tanstack-start-v1-vite-v7-production-rpc-manifest-v2` /
  `tanstack-start-build-observation-v2` / observer `0.2.0`.

Each native archive runs the same static/semantic/build union fixture through
build-filtered dependency queries, snapshot diff, reverse impact, architecture
policy, JSON and GraphML export, an equivalent second checkout, and a failed
build rollback. The four observer bundles and shared converter are
dependency-free first-party packages in SPDX, with exact manifest checksums and
root `CONTAINS` relationships.

## Performance

The benchmark uses a deterministic 10,000-source-file fixture and records each
raw sample rather than reporting only an aggregate. The product targets remain
30 seconds for a fresh initial scan, 2 seconds for one-file incremental work,
and 500 milliseconds for a warm impact query.

The release gate enforces the incremental product target directly and retains
explicit hosted-runner ceilings for the other metrics. The latest macOS
pre-release validation recorded:

| Metric | Release ceiling | Latest local result |
| --- | ---: | ---: |
| Fresh initial scan median | `80 s` | `32.885 s` |
| One-file watcher incremental median | `2 s` | `514 ms` |
| Warm file impact median | `500 ms` | `31 ms` |
| Warm package impact median | `500 ms` | `32 ms` |

The gate permits at most one bounded outlier and applies a 20% hard noise limit.
The local run also recorded a Rust HIR scan at `1.030 s`, a Rust query at
`30 ms`, and build observation at `3.456 s`. It proved that the watched file
changed while graph topology, dependency-site, edge, evidence, and coverage
digests were conserved. These numbers describe the tested machine; they
are not a guarantee for every repository or machine.

## Safety boundary

Safe scans do not execute project configuration, plugins, package managers,
generators, build scripts, proc macros, or project-local compiler binaries.
Repository toolchain aliases, relative `PATH` entries, Node execution hooks,
out-of-root symlinks, undeclared runtime-tree entries, and manifest/checksum
mismatches fail closed.

Build observation remains an explicit privileged operation:
`resolve --build` requires `--allow-project-code`, executes supervised project
code, records that boundary in the store, and preserves the previous completed
snapshot after crash or timeout.

Runtime traces are bounded by size, event count, nesting, and identifier length.
They carry environment/header/secret names and redaction counts, never secret
values. Repository, revision, profile, locator, and node matching are validated
against a completed snapshot before import. Failed import cannot replace the
current completed snapshot.

The watcher uses a single-writer lock, ignores its own database/status files,
coalesces changes deterministically, and publishes a completed snapshot only
after the replacement scan succeeds. Snapshot names are immutable. GraphML file
output rejects symlink/non-regular/read-only destinations and replaces the
destination only after a complete successful write.

## Known limitations

- One-file Web writes with an unchanged dependency-analysis fingerprint use a
  one-node validation projection and sparse snapshot overlay. Semantic edits,
  Rust/Go, workspace replans, and complete-reanalysis closures above the
  4,096-path exact-base materialization bound retain the atomic full-scan
  fallback.
- The versioned benchmark directly enforces the 2-second one-file watcher
  product target and records daemon phase timings for regressions.
- Runtime evidence is imported from an external collector contract. This
  release validates and persists traces but does not ship a production runtime
  collector.
- Architecture policy evaluates evidence already present in selected completed
  snapshots; it cannot prove dependencies omitted by an incomplete profile.
- Dynamic/build-only framework routes, reflection, native callbacks, proc-macro
  output, and open dispatch remain explicit candidate/external/unresolved
  boundaries rather than fabricated exact edges.
- Rust `1.93.1` `rust-src` is bundled and checksum-attested as a licensed
  `rust-stdlib-source` data tree. After core verifies the complete tree, the
  packaged HIR adapter maps `core`, `alloc`, and `std` into an inventory-only
  library VFS and emits exact standard-library symbol, type, import, type-use,
  and direct-call edges. Development or failed-attestation paths retain syntax
  output without `semantic-complete` and never fall back to project or system
  `rust-src` or backend bytes.
- GraphML is a lossless depgraph interchange export, but third-party viewers may
  ignore the canonical JSON stored in profile/site/evidence data keys.
- This is a prerelease compatibility candidate, not a stable `0.4.0`
  declaration.

## Published artifacts

The release workflow publishes archives and SHA-256 sidecars for:

- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`
- `x86_64-apple-darwin`
- `aarch64-apple-darwin`
- `x86_64-pc-windows-msvc`

Each archive contains the core, Rust/Go/Web workers, protocol schema, required
Web runtime components, the pinned Rust standard-library source data tree,
`release-manifest.json`, `sbom.spdx.json`, both complete
project licenses, and the separated third-party license inventory. The manifest
attests every file/tree digest, worker/backend compatibility unit, runtime
requirement, store/cache/schema contract, native package smoke contract, and
the ordered four-framework build capability ledger.

After all five native package jobs pass, the aggregate verifier re-downloads
the exact archive/checksum set and rejects missing, duplicate, extra, symlinked,
tampered, or incompatible assets. It writes `release-verification.json`, which
includes the compatibility unit and per-target archive, manifest, SBOM,
license, worker, Rust sysroot tree, and framework build artifact digests. It
rejects a target set whose Rust sysroot, observer/converter bytes, or SPDX
closure differ. The verified benchmark report and verification
report are attached to the GitHub prerelease.

## Release workflow

The tag workflow must complete these jobs before publication:

- `quality`: formatting, lint, Rust/Go/Web tests, race tests, and semantic E2E.
- `benchmark`: the versioned 10,000-file benchmark and conservation gate.
- `package`: native package and Milestone 4 smoke verification on all five
  targets.
- `verify-assets`: aggregate checksum, manifest, compatibility, SBOM, license,
  attestation, and benchmark verification.
- `publish`: GitHub prerelease creation from the verified tag.

Representative packaged usage:

```sh
depgraph doctor --json
depgraph scan /path/to/repository --json
depgraph snapshot create baseline --json
depgraph daemon start /path/to/repository
depgraph diff baseline current --json
depgraph impact path:src/app.ts --changed origin/main --json
depgraph policy baseline current --github-annotations
depgraph runtime validate runtime-trace.json --json
depgraph runtime import runtime-trace.json --json
depgraph export --format graphml --output graph.graphml
```
