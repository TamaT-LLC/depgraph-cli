# depgraph v0.4.0-rc.5

This release candidate republishes the complete `0.4.0` release closure with
target-aware aggregate smoke verification. It supersedes rc.4, whose five
normal package jobs completed successfully but whose aggregate verifier treated
target-native bounded-query and profile-plan identities as target-independent
bytes.

Bounded-query plans bind the closed graph produced for each native target, and
profile plans bind Rust and Go host contexts. Their raw digests are therefore
expected to differ by target. Each package still executes the query and profile
planner twice against checkout-equivalent repositories and requires exact byte
stability within that target. The aggregate and stable release gates retain the
exact native digests, bind them through the smoke report and archive checksums,
and compare every target to the compiled five-target release expectations. The
native package gate derives those values by executing the extracted archive, so
a syntactically valid forged sidecar digest is rejected before aggregation.
Truly target-independent runtime, framework-build, cross-language, schema, and
license artifacts remain byte-identical aggregate requirements.

Release staging also preserves the rc.4 fixes: contract text is canonical
UTF-8/LF on every target, and Windows ZIP staging records `.exe`, `.cmd`, and
`.bat` files with the executable modes required by compiler-pack verification.

## Compiler-pack assets

Each of the five supported targets publishes these assets in addition to the
normal depgraph archive:

- `depgraph-compiler-pack-0.4.0-<target>.tar.gz` (or `.zip` on Windows)
- the matching `.sha256` sidecar
- `depgraph-compiler-pack-0.4.0-<target>.requirement.json`
- `depgraph-compiler-pack-0.4.0-<target>.smoke.json`

The aggregate `compiler-pack-verification.json` binds all five packs.
`stable-release-gate.json` binds that report to the normal archive matrix and
rejects a missing target, version or target drift, failed semantic smoke,
tamper/rollback failure, or a failed compiler-pack workflow job.

Download and extract the matching pack next to its requirement document, then
verify it before running project code:

```text
depgraph doctor --compiler-pack-requirement compiler-pack-requirement.json
depgraph resolve --build PATH --allow-project-code --rust-compiler-precise \
  --compiler-pack-requirement compiler-pack-requirement.json
```

See the compiler-pack section in the README for platform-specific checksum and
extraction commands. No rustup, PATH, system, project-toolchain, or alternate
backend fallback is attempted.
