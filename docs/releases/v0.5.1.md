# depgraph v0.5.1

この文書は`v0.5.1`のstable release noteである。
ソースにこの文書が存在するだけでは、公開完了を意味しない。
`v0.5.1`が有効な正式版になるのは、署名付きannotated tag、[GitHub Release](https://github.com/TamaT-LLC/depgraph-cli/releases/tag/v0.5.1)、`release-post-publish-evidence-v0.5.1.json`が存在し、同じcommitと公開assetを指す場合に限る。

`v0.5.1`は、npmから導入できる最初のstable versionである。
既存の`v0.5.0` GitHub Release、tag、asset、公開後証跡は変更しない。

## npm配布

npmでは、TamaT LLCのorganization scopeに次の6 packageを公開する。

- `@tamat-llc/depgraph`
- `@tamat-llc/depgraph-darwin-arm64`
- `@tamat-llc/depgraph-darwin-x64`
- `@tamat-llc/depgraph-linux-arm64-gnu`
- `@tamat-llc/depgraph-linux-x64-gnu`
- `@tamat-llc/depgraph-win32-x64`

利用者はroot packageだけを指定して導入する。

```sh
npm install --global @tamat-llc/depgraph
depgraph --version
depgraph-mcp --version
```

root packageは`depgraph`、`depgraph-cli`、`depgraph-mcp`の3 commandを提供する。
対応するnative packageはnpmの`os`と`cpu`により選択され、launcherはpackage内の検証済み実行ファイルだけを起動する。
install時のlifecycle scriptと外部downloadは使用しない。

公開workflowは、5つのnative packageを先に公開し、root packageを最後に公開する。
公開にはnpm Trusted PublishingのOIDCを使用し、長期npm tokenをGitHub Actionsへ保存しない。
各tarballのpackage名、version、repository、SHA-256、npm integrityは、同一workflowで生成した閉じたinventoryと照合する。

## 互換性

`v0.5.1`は`v0.5.0`と同じv0.5互換性境界を維持するpatch releaseである。

| Surface | `v0.5.1` contract |
| --- | --- |
| Product and Rust/Go/Web adapters | `0.5.1` |
| Previous stable release | `v0.5.0`, Store schema `17` |
| NDJSON worker protocol / graph schema | `1.0` |
| SQLite Store | schema `17` |
| Durable operation journal | schema `5` |
| MCP tool DTO | `depgraph-mcp-tools-v1` |
| Operation DTO | `depgraph-operation-v1` |
| Agent host configuration | `depgraph-agent-host-config-v1` |
| Agent onboarding release evidence | `release-post-publish-evidence-v1` |
| Packaged MCP smoke | `mcp-package-smoke-v2` |
| Native package smoke | `stable-v0.5.0-packaged-smoke-v1` |
| Stable release gate | `stable-release-gate-v2` |

Store schema、operation journal schema、worker protocol、MCP DTOに変更はない。
`v0.5.0`のStoreはmigrationなしで開ける。
古いStoreに対する検証は、引き続き公式`v0.4.0-rc.6` schema-13 fixtureからschema 17へのtransactional migrationとbyte不変のrollback copyを使用する。
対象fixtureは`xtask/fixtures/v0.4.0-rc.6-store-v13.sql`であり、SHA-256は`43fe0dda73d03be9b8fff2ed9ff8ce888ad96e41e78335a1117646475c937150`に固定する。

`stable-v0.5.0-packaged-smoke-v1`という識別子は、v0.5系で固定したsmoke contractの名前であり、製品versionの取り違えではない。
このpatch releaseでもcontract名を変更しないため、`v0.5.0`と`v0.5.1`の検証結果を同じ意味で比較できる。

## Release sourceと公開条件

stable baseline statusは`maintenance-ref-pinned`である。
`v0.5.1`のsourceは、remote `main`、`refs/heads/release/0.5`、署名付きtagが同じcommitを指す場合だけ受け入れる。
tag作成前には、そのexact `main` commitで8 jobの手動Full CIを完走させる。
Release workflowは5 targetの通常archive、compiler pack、checksum、smoke report、benchmark、aggregate reportを再構築し、公開後にGitHub Releaseから再取得してbyte一致を検証する。

GitHub Releaseと`release-post-publish-evidence-v0.5.1.json`の生成が完了した後、`npm-release.yml`を`v0.5.1` tagへdispatchする。
npm workflowはGitHub Releaseの公開byteから6 packageを生成し、GitHub Environment `npm`の承認境界を通って`latest`へ公開する。
bootstrap placeholderが持つ`latest`は、このstable publicationにより`0.5.1`へ移る。

## 既知の制約

Safe scanは対象repositoryのbuild script、plugin、package managerを実行しない。
Compiler-precise modeとframework build observationは、明示的な同意と一致するcompiler packを要求する。
未対応、未解決、曖昧な依存関係は推測で`resolved`へ昇格しない。
Storeのdowngrade-in-placeと異なるversionのnative packageを混在させる構成はサポートしない。

製品サポートはベストエフォートであり、応答時間や解決時間のSLAは設けない。
