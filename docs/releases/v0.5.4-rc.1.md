# depgraph v0.5.4-rc.1

`v0.5.4-rc.1` は評価用の release candidate である。
説明可能な code-health 解析と Agent dogfood v2 を公開配布物で検証する。
既存の stable `v0.5.4` を置き換えるものではない。
stable `v0.5.4` の Store schema `17` とその互換性契約は immutable なまま保持する。
この候補では、tag 後の `main` が持つ未公開の Store schema `18` 契約を検証する。

この候補の評価結果をもとに、次の stable の minor version と migration／contract version を別途決定する。
この候補を stable 利用者へ配布したり、`v0.5.4` の stable artifact と同一契約として扱ったりしてはならない。

この候補の主目的は、Issue #436 の Phase 2 として、Apple Silicon 向け archive、
compiler pack、`mcp-package-smoke-v3` を固定し、実 Agent host が配布物だけで
code-health query を完遂できることを再現可能な evidence にすることである。
ソースにこの文書が存在するだけでは公開完了を意味しない。公開には、exact Full CI
を通過した `main` commit を指す署名付き annotated tag、GitHub Release、同じ
commit と公開 asset を指す post-publish evidence が必要である。

## Code-health surface

read capability の MCP server は、既存の依存グラフ query に加えて次の tool を公開する。

- `health_summary_get`
- `health_findings_list`
- `health_finding_get`
- `health_hotspots_list`
- `health_audit_get`

finding は kind、severity、confidence、blocker、evidence、remediation、stable ID、fingerprint を保持する。
`confirmed` は未使用を証明する4種類のfindingだけに使用する。
`test-only-dependency`、`manifest-mismatch`、audit、hotspotは`probable`を上限とする。
confidence は engine の判定をそのまま扱い、Agent が昇格してはならない。
`churn-unavailable` と `runtime-not-observed` は hotspot の score layer を低下させる。
それ以外の hard blocker は unused finding の`confirmed`判定を禁止する。

Agent dogfood v2 は `unused-file` finding の一覧と詳細、hotspot、base snapshot 付き
changed-code audit を検証する。候補 snapshot には、実 scan で最低 1 件の
`unused-file` finding を生成する意図的に未参照の TypeScript probe が含まれる。

| Operation DTO | `depgraph-operation-v1` |

worker protocol、operation journal、既存 CLI の既定値は `v0.5.4` と同じである。
一方、候補の Store は tag 後の `main` と同じ schema `18` を使用する。
stable の schema `17` から schema `18` へ transactional migration できることを検証する。
異なる version の binary、worker、compiler pack、manifest、Store を一つの実行環境で混在させない。

## Store migration and rollback

schema `17` から schema `18` への移行は一つの transaction で完結する。
途中で失敗した場合は全体を rollback し、部分的な Store を公開しない。

候補の migration gate は、checksum 固定した公式 `v0.4.0-rc.6` schema-13 fixture を schema `17` まで移行してから schema `18` へ進める。
completed snapshot の graph identity と既存データを保持する。
legacy snapshot seal `v1` を検証し、health provenance を結合した provenance-aware snapshot seal `v2` を再構築する。

移行前にdaemon、MCP server、operation runnerを停止する。
Storeを開くその他のprocessも停止する。
CLIから新しいrequestを開始してはならない。
受理済みoperationはterminal状態まで進めるか、cancelしてterminal状態までpollする。
すべてのread requestとworkerが終了するまで待つ。
stdioのcloseまたはwriter lockの取得だけでは、quiescenceとはみなさない。
各read requestの`RequestReadStore`をdropする。
対象Storeを開いているSQLite connectionが残っていないことを確認する。
このquiescenceが成立してから、databaseとWAL／SHMを一組のbackupとして保存する。
schema `18` へ移行した database を、公開済み stable `v0.5.4` またはそれ以前の
binary で開く downgrade-in-place は禁止する。
rollback時も新binaryを停止し、同じquiescenceが成立するまで待つ。
schema-18 databaseを診断用に保全したうえで、移行前のdatabaseとWAL／SHM一式をbyte-for-byteで復元してから旧binaryを起動する。
host全体の停止手順は[mcp-agent-host-operations.md](../50_test/mcp-agent-host-operations.md#upgrade-and-rollback-policy)を正本とする。

## Release closure

候補 tag の peeled commit は remote `main` と一致し、その exact commit の手動 Full CI
8 job がすべて成功していなければならない。Release workflow は 5 target の通常 archive
と compiler pack を再構築し、checksum、manifest、SBOM、license、package smoke、
compiler handshake、stable gate を検証する。

公開後は GitHub Release から全 asset を再取得し、workflow artifact と byte 一致する
ことを確認する。`release-post-publish-evidence-v0.5.4-rc.1.json` は candidate commit /
tree、署名 tag object、Full CI、Release run、asset digest と aggregate report を同じ
候補へ固定する。push 済み tag と公開 asset は移動・置換しない。修正が必要な場合は
新しい RC 番号を使う。

## Known constraints

- Release candidate は評価用であり、stable support SLA を持たない。
- Safe scan は project code、build script、plugin、package manager を実行しない。
- Compiler-precise mode と framework build observation は、明示的な同意と一致する
  compiler pack を要求する。
- Agent dogfood v2 の実 evidence と digest pin は、この候補の公開 closure が完成した後、
  別の review 済み PR で固定する。
