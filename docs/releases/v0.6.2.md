# depgraph v0.6.2

`v0.6.2`はv0.6.1に対するstable patch releaseであり、Webスキャン、pnpmのビルド連携、大規模解析の再開とhealth判定を修正する。
この文書の追加だけでは公開完了にならない。署名付きtag、GitHub Release、同一sourceの公開後証跡を必要とする。

## Web スキャンのルート重複と型参照

TanStack Router の生成ルートで、レイアウトと index が同じ `fullPath` を持つとスキャンが停止する問題を修正した（[#510](https://github.com/TamaT-LLC/depgraph-cli/issues/510)）。
同じ論理ルートの識別子を保ち、各出現位置の根拠を統合する。

TypeScript の未解決の名前空間参照と、`Error` / `ErrorConstructor` のように値と型の symbol が異なる継承を、不正な応答と誤判定する問題を修正した（[#511](https://github.com/TamaT-LLC/depgraph-cli/issues/511)）。
`typeof` の型解決に成功した後も、途中の失敗理由が残って依存グラフを破棄する問題を修正した（[#512](https://github.com/TamaT-LLC/depgraph-cli/issues/512)）。
未解決箇所の診断と、不正なコンパイラー応答を拒否する検証は維持する。
CLI の既定値、公開プロトコル、Store スキーマ、依存パッケージの変更はない。

## Homebrew での導入

macOS / Linux 向けに `brew install tamat-llc/tap/depgraph` を案内する。
初回の導入後は `brew install depgraph` と `brew upgrade depgraph` に省略できる。
公式パッケージを全体で保持し、Node.js 24 系を依存関係として導入する。
Stable の公開後、署名付き tag と公開後証跡を検証して tap の更新 PR を作成する。
npm の導入方法と公開プロトコルは変更しない。

v0.6.1までのビルド連携・失敗診断の修正は [v0.6.1](v0.6.1.md) を参照する。

## pnpm の依存解決を保つビルドステージング

`resolve --build` で `node_modules` 内の安全なシンボリックリンクを保持し、コピー先内の相対リンクとして作成する。
pnpm の isolated layout で依存パッケージが複数バージョン共存する場合も、実体化によってネストした依存の解決先が変わる問題を防ぐ（[#506](https://github.com/TamaT-LLC/depgraph-cli/issues/506)）。
リンクの種類と参照先を入力 fingerprint に含め、同じ内容を持つ別バージョンへの付け替えも検出する。
Next の Node.js トレースが返す依存ディレクトリリンクにも対応し、閉じた参照先と観測前後の同一性を検証したリンク構造を記録する。主出力・fallback・Wasm は通常ファイルの要件を維持する。
実アプリで検出した Edge asset のパス基準の相違も修正し、ビルド出力ディレクトリ相対名と絶対パスが同じリポジトリ内ファイルを指す場合だけ受け入れる。
ページ・RSC/data・事前生成結果で Next が再利用する出力 ID を型とバリアントで区別し、親参照は一意な主リクエスト経路に解決する。曖昧な親や同一バリアント内の重複を黙って統合しない。
サーバーと Edge が同じ manifest を共有する場合は、役割を含む asset の識別子で両方の読み込み関係を保持し、異なる属性を持つ同一ノードとして衝突させない。
実アプリの正当な証跡付きグラフが約 35 MB になるため、Web 証跡変換の標準出力上限を入力と同じ 64 MiB にした。読み込み中の保持量を制限し、標準エラーは 64 KiB、処理は 30 秒で制限する。上限超過した結果を部分的に採用せず、protocol・graph・store の検証を維持する。runtime trace と query の 16 MiB 上限には影響しない。
リポジトリ外・dangling・特殊ファイルへのリンクは引き続き拒否し、管理用ディレクトリと明示的な除外先へのリンクはコピーしない。
依存関係・公開プロトコル・Store スキーマの変更はない。

## 未解決依存がある場合の health 判定

完了した解析の実行記録から未解決依存の範囲を証明できる場合、health の保留理由を該当する言語アダプターに限定する。
たとえば Web だけに未解決依存がある場合、Go の未使用候補まで同じ理由で保留しない。
実行記録がない場合、未知の形式や未完了の記録がある場合、追加のビルド・実行観測を重ねた場合は、従来の保留を維持する。
公開API、生成コード、曖昧な参照、プロファイル不足による保留は引き続き適用する。
全件読み込みと範囲別処理で同じ判定を使い、health analyzer を `1.0.4` に更新して以前のチェックポイントを区別する。
既存のスナップショット識別子と Store のスキーマバージョンは変更しない。

## Web の増分解析とベンチマーク性能

分割解析後も、依存関係と位置情報に影響しないコメント追加は、一つのファイルの内容ハッシュだけを更新する。
変更が解析結果に影響しないことを worker と保存処理で検証し、元の snapshot のグラフと解析完了記録を引き継ぐ。
引き継いだ実行記録の scan ID と入力 fingerprint は元の値を保持する。
解析記録がない場合、実行が未完了の場合、設定や依存関係が変わった場合は再解析する。
この増分更新は Web の解析単位だけを持つスナップショットに限定し、Go・Rust が混在する場合は再解析する。

ベンチマーク CI は途中で失敗しても、取得済みの計測値と daemon の状態を artifact に残す。
手動実行の `benchmark_only` では、Rust・Go・Web の検査とベンチマークを実行する。

分割解析では、利用しないスナップショットキャッシュの計算・保存と、重複する worker の機能確認を省く。
入力・設定・worker・実行環境の変更確認は維持する。
キャッシュ性能検証は各解析単位の再利用記録を確認し、通常の再解析とのグラフ一致と 5% 以上の高速化を引き続き要求する。

初回スキャンの既定の分割サイズを 128 ファイルから 2,048 ファイルに変更した。
小さなファイルが多いプロジェクトで、同じコンパイラー環境を過剰に作り直す回数を減らす。
worker ごとのメモリ・出力・無進捗時間の上限と、同時実行数による制限は引き続き適用する。
上限に達した分割は、完了済みの結果を保持して再分割する。
`.depgraph.toml` に明示した `max_unit_source_files` はそのまま優先する。

副作用だけの `import` の連鎖で、不要な宣言まで AST として収集し、意味解析の完全性を失う問題を修正した。
型検査には全ソースを渡し、名前付き参照とグローバル宣言に必要な AST は保持する。
転送対象外のソースに型エラーや構文エラーがある場合も、意味解析を完全とは判定しない。

## 大規模解析の再分割と macOS の再利用

メモリ上限・タイムアウト・出力量上限で失敗した batch を再分割するとき、成功済みの batch の番号を保持するように修正した。
保存側も再分割の世代を考慮し、全 batch の存在・番号の一意性・解析範囲を確認してから完了と判定する。
再分割が終わるまで失敗時の部分出力を一時保存し、置き換え前後の profile が衝突しないようにした。
回復できない場合は部分結果を保持する。
再分割の計画・実行・記録の更新がエラーで終了した場合も、置き換えられていない部分結果を復元してからエラーを返す。
大きなprotocol出力の検証は専用の処理スレッドで行い、別workerのパイプ読み取りや上限監視を妨げないようにした。
個別の資源上限は変更しない。
完了時の snapshot 識別子は、グラフ全体の JSON を複製せず、一件ずつ正規化してハッシュを計算する。
既存の識別子・保存形式を維持しながら、完了処理の一時メモリを削減した。
再分割した計画の履歴を保存し、同じ入力・設定・worker での次回スキャンに復元する。
一時的な資源不足が解消した後も、元の大きな単位に戻らず、完了済みの小さな単位を再利用できる。
履歴が壊れている場合や入力が変わった場合は元の計画から始め、`--no-cache` では履歴を使わない。
事前の依存計画では、Go のモジュール名の最長一致、Web の import 構文、Node 標準モジュール、TypeScript のパス別名・継承設定、ロック済みの外部依存を扱う。
文字列や Markdown のコード例を参照先と誤認して、解析済みの単位を未完了と判定する問題を修正した。
解決できない参照は引き続き不明として記録し、継承設定も再利用時の入力確認に含める。
全単位の実行完了と意味解析の確実性を分け、未解決参照だけを理由に scan を partial としない。
その場合も集計に semantic-complete を付けず、診断を保持し、health の未使用確定を抑止する。
Web の内蔵 TypeScript コンパイラーのタイムアウトも再分割対象として扱い、汎用の失敗で止まらないようにした。

macOS の Go 解析でも、リポジトリ内依存の参照 fingerprint を生成できるようにした。
Linux と共通の `openat` と `O_NOFOLLOW` による読み込みを使い、参照元の変更を検出しながら package semantic の結果を再利用する。
この経路の Go race/vet 検証は、通常の pull request と main push の macOS CI でも実行する。
既存依存の Go 公式拡張パッケージ `golang.org/x/sys v0.47.0`（BSD-3-Clause）を利用する。

元の試験対象での scan と health の完了確認は、Epic #464 の必須条件として扱う。
公開合成 fixture の成功や、部分グラフに対する health の成功だけでは完了扱いにしない。

関連: [#479](https://github.com/TamaT-LLC/depgraph-cli/issues/479)、[#480](https://github.com/TamaT-LLC/depgraph-cli/issues/480)、[#482](https://github.com/TamaT-LLC/depgraph-cli/issues/482)。

## Release source and verification

1. version change、release note、ADRを一つのPRにまとめ、CI成功とGreptileの未解決指摘ゼロを確認してマージする。
2. `main`を一時freezeし、そのcommitで`extra_native_packages=true`を指定したmanual Full CIの10ジョブすべてを成功させる。Intel macOS（`macos-15-intel`）は対象外である。
3. `refs/heads/release/0.6`を同じcandidate SHAに作成する。既存refならfast-forwardで更新する。
4. `v0.6.2`のsigned annotated tagを同じsource SHAへ作成する。
5. Release workflowで4 targetのarchive、compiler pack、checksum、manifest、SBOM、license、MCP smokeを検証する。`x86_64-apple-darwin` は構築しない。
6. 公開後にasset closure、stable gate、code-health CLI/MCP parity、Agent host canaryを検証し、`release-post-publish-evidence-v0.6.2.json`を同じReleaseへ追加する。
7. GitHub Releaseと証跡が成立した後に、npm workflowを`v0.6.2`へdispatchする。

`v0.5.4`のtag object、peeled source、asset、evidenceをv0.6.2のcandidateとして再利用しない。

v0.6.2は`@tamat-llc/depgraph`と`@tamat-llc/depgraph-win32-x64`を含む4 targetのnative packageを公開する。`@tamat-llc/depgraph-darwin-x64` は公開しない。
npm publicationには`npm Trusted Publishing`を使い、Node.js 24以上を要求する。
musl targetは対象外であり、`v0.6.2`のnative jobは`mcp-package-smoke-v3`を使う。
stable gateは製品価値の`agent-dogfood-report-v1`に加え、Issue #436のcode-health `agent-dogfood-report-v2`を14 gateで検証する。
code-health reportは`fixtures/agent-dogfood-v2/evidence/v0.5.4-rc.2/report.json`に固定する。
code-health reportの固定SHA-256は`7cb90ae38161e375ac080f475de6c8ab36dc18afc3ce243f6cdf7306d759547f`である。
