# depgraph v0.5.0 candidate contract

Status: unreleased. This document defines the v0.5 release contract; it does
not claim that a stable GitHub Release exists. The stable baseline status is
`candidate-unpinned`, so `v0.5.0` publication is blocked until the GA review
pins an exact full-CI-green commit. Release candidates use canonical
`v0.5.0-rc.N` tags.

## Compatibility tuple

| Component | v0.5.0 contract |
| --- | --- |
| Product and Rust/Go/Web adapters | `0.5.0` |
| NDJSON worker protocol / graph schema | `1.0` |
| SQLite Store | schema `17` |
| Minimum migratable Store schema | `1` |
| Canonical upgrade source | `v0.4.0-rc.6`, Store schema `13` |
| Durable operation journal | operation journal schema `5` |
| MCP tool DTO | `depgraph-mcp-tools-v1` |
| Operation DTO | `depgraph-operation-v1` |
| Agent host configuration | `depgraph-agent-host-config-v1` |
| Agent onboarding release evidence | `release-post-publish-evidence-v1` |
| Packaged MCP smoke | `mcp-package-smoke-v2` |
| Native package smoke | `stable-v0.5.0-packaged-smoke-v1` |
| Stable release gate | `stable-release-gate-v2` |

All Cargo workspace packages, Rust/Go/Web adapter handshakes, native binary
versions, release manifest and SBOM package versions, archive names, compiler
pack names, and MCP documentation paths derive from the exact `0.5.0` base
version. A current package rejects `v0.4.0`, every `v0.4.0-rc.N`, malformed
`v0.5.0-rc.01`, and any unrelated tag.

The packaged CLI's Agent onboarding preflight parses `.tar.gz` and `.zip`
release archives directly. `flate2`, `tar`, `zip`, and their transitive runtime
closure are therefore included in the release SBOM and third-party license
inventory rather than treated as xtask-only dependencies.
It also requires the official `release-post-publish-evidence-v1` asset and that
asset's SHA-256 obtained independently from GitHub release metadata. The closed
record binds the selected archive, checksum, and target compiler-pack
requirement to the official 51-asset release closure before any packaged
executable starts; a digest calculated from the local evidence file is not a
trust anchor.

## Upgrade and rollback

1. Stop the daemon, MCP server, operation runner, and every Store writer.
2. Close SQLite cleanly and copy the database plus matching WAL/SHM files as
   one backup set.
3. Record a checksum for every backup file before opening the Store with v0.5.
4. Open the original with v0.5 and verify schema 17, current snapshot identity,
   integrity, and required queries before resuming writers.
5. Retain the pre-upgrade backup for the rollback window.

The package test keeps the pre-upgrade database bytes and verifies they remain
unchanged. Downgrade-in-place is unsupported: an rc.6 or other old binary must
not open the migrated schema-17 database. To roll back, stop v0.5, preserve the
migrated database separately, restore the complete checksum-matching backup
set, and then start the previous binary.

The operation journal is a separate database. Its schema `5` migration and
rollback rules remain owned by `depgraph-operation-v1`; Store files and journal
files must never be substituted for one another.

## Tag, source, and maintenance policy

- `v0.5.0-rc.N` accepts only a positive, no-leading-zero RC sequence and binds
  the release artifacts to that tag's exact source SHA.
- `v0.5.0` is rejected while the baseline status is `candidate-unpinned`.
- The GA task must record the reviewed commit, tree, baseline digest, full CI
  run, artifact closure, and independent approval before enabling stable.
- `refs/heads/release/0.5` is created at that exact GA baseline, not before.
- Published tags and assets are immutable. A fix receives a new RC or patch
  version.
- The default-branch guard continues to protect the reserved v0.4 baseline
  and separately blocks unpinned v0.5 stable publication.

## v0.4 history and current support

The latest published GitHub Release before v0.5 is `v0.4.0-rc.6`. No
`v0.4.0` stable GitHub Release was published. The v0.4 baseline commit, tree,
digest, `release/0.4` ref, RC tags, and RC assets remain unchanged historical
evidence. They do not form a supported stable line.

Until v0.5 GA is published, the project has no supported stable release.
`main` and release candidates are evaluation builds maintained on a best-effort
basis without an SLA. GA updates the support documents only after the pinned
stable tag and release assets exist.

- [ ] The rc.6 fixture checksum and provenance match this document.

      `depgraph-mcp-tools-v1`, `depgraph-operation-v1`,

      `mcp-package-smoke-v2` match every manifest, generated host entry, and

      and Greptile review are green with no unresolved finding.
