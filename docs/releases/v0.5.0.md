# depgraph v0.5.0

This is the canonical stable release note. Its presence in source is not proof
that publication completed: the stable release exists only when the immutable
[`v0.5.0` GitHub Release](https://github.com/TamaT-LLC/depgraph-cli/releases/tag/v0.5.0),
signed annotated tag, and `release-post-publish-evidence-v0.5.0.json` all
exist and agree. The baseline status is `maintenance-ref-pinned`; the release
workflow still fails closed unless `main`, `refs/heads/release/0.5`, the tag,
and the exact all-green Full CI run all identify one source commit.

## Upgrade and rollback

1. Stop the daemon, MCP server, operation runner, and every Store writer.
2. Close SQLite cleanly and copy the database plus matching WAL/SHM files as
   one backup set.
3. Record a checksum for every backup file before opening the Store with v0.5.
4. Open the original with v0.5 and verify schema 17, current snapshot identity,
   integrity, and required queries before resuming writers.
5. Retain the pre-upgrade backup for the rollback window.

The package test keeps the pre-upgrade database bytes and verifies they remain
unchanged. Downgrade-in-place is unsupported: an rc.6 or other old binary must
not open the migrated schema-17 database. To roll back, stop v0.5, preserve the
migrated database separately, restore the complete checksum-matching backup
set, and then start the previous binary.

The operation journal is a separate database. Its schema `5` migration and
rollback rules remain owned by `depgraph-operation-v1`; Store files and journal
files must never be substituted for one another.

## Tag, source, and maintenance policy

- `v0.5.0-rc.N` accepts only a positive, no-leading-zero RC sequence and binds
  the release artifacts to that tag's exact source SHA.
- `v0.5.0` is accepted only when its source is simultaneously the remote
  `main` head and the initial `refs/heads/release/0.5` head. A missing or
  different ref causes the default-branch guard to cancel the Release run and
  delete the invalid tag.
- `stable-release-gate-v2` independently requires a successful
  `workflow_dispatch` CI run on that exact `main` SHA with the eight canonical
  job names, plus the pinned dogfood report. The publish job rechecks remote
  `main` before uploading anything.
- The exact commit, tree, Full CI run, Release run, 51-asset closure, and tag
  object are recorded in `release-post-publish-evidence-v0.5.0.json`.
- The canonical baseline digest is SHA-256 over
  `release-baseline-v1\nrepository=TamaT-LLC/depgraph-cli\nversion=0.5.0\ncommit=<exact-commit>\n`.
  The gate records this digest beside the exact runtime-selected commit; no
  source file attempts an impossible self-reference to its own commit SHA.
- Published tags and assets are immutable. A fix receives a new RC or patch
  version.
- The default-branch guard continues to protect the reserved v0.4 baseline
  and separately protects the v0.5 main/maintenance/tag identity.

## Support matrix and known limitations

| Surface | Stable support |
| --- | --- |
| Native archives | Linux x86-64/ARM64, macOS Intel/Apple Silicon, Windows x86-64 |
| Languages | Rust, Go, TypeScript/JavaScript and the documented framework/cross-language profiles |
| MCP hosts | Codex, Claude Desktop, VS Code; read-only configuration is the default |
| Store upgrade | schemas `1` through `17`; canonical evidence covers rc.6 schema `13`, rc.1 schema `11`, and legacy schema `5` |
| Maintenance | best effort on `release/0.5`; no response-time or resolution-time SLA |

Known limitations are intentional safety boundaries. Safe scan does not run
project code. Compiler-precise and build-observation modes require explicit
consent and the exact compiler pack. Unsupported, unresolved, or ambiguous
dependencies remain typed as such rather than being guessed. Host onboarding
requires the complete archive, checksum, compiler requirement, and
independently trusted post-publish evidence digest. Downgrade-in-place is not
supported, and mixed-version package trees are rejected.
